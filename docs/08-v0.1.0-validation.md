## 2. 最终核心数据模型

### Source Object

```text
wp_posts
```

默认语言 Source Data 保持原始状态。

### Source Units

```text
wp_wem_ml_strings
```

核心原则：

> **Context 定身份。**

例如：

```text
post:44:title
```

### Translations

```text
wp_wem_ml_translations
```

核心原则：

> **Hash 定版本。**

通过：

```text
source_hash
translated_from_hash
```

判断 Current / Stale。

### Object Language State

```text
wp_wem_ml_object_state
```

核心原则：

> **State 定发布边界。**

状态：

```text
draft
published
```

### Object Slugs

```text
wp_wem_ml_object_slugs
```

路由真相：

```text
object_id
+
language
+
translated_slug
```

完整 Public URL 属于 Derived Data。

## 8. T05 — Stale Detection

实验过程中验证：

```text
Live Source Hash
Stored Source Hash
Translation From Hash
```

### Current

```text
Live Source Hash
=
Stored Source Hash
=
Translation From Hash
```

### Source Drift

WordPress Source 已修改、Source Unit 尚未同步：

```text
Live Source Hash
!=
Stored Source Hash
```

Runtime Overlay 自动停止。

### Stale

Source Unit 已同步，但 Translation 仍对应旧版本：

```text
Stored Source Hash
!=
Translation From Hash
```

旧译文保留，但不作为 Current Translation 使用。

最终验证：

> **Context = Identity，Hash = Version。**

### 模板兼容要求

实验过程中确认：

```html

```

这种静态模板写法无法被 Core 正确切换语言。

模板应使用 WordPress 原生：

```php
<html <?php language_attributes(); ?>>
```

## 12. T09 — Disable Safety

第一次测试发现真实问题：

```text
插件停用后
/es/acerca-de-evodek/
仍然 HTTP 200
```

同时页面：

```text
html lang=en
```

这证明 Runtime Code 已停用，但 WEM Rewrite Rule 仍残留。

### 根因

原停用逻辑：

```php
flush_rewrite_rules();
```

在插件停用请求中，WEM Rewrite Rule 已经在本次请求的 Rewrite 集合中注册。

只调用 flush 可能重新持久化该规则。

### 修复

最终采用：

```text
显式移除 WEM 自己的 Rewrite Rule
↓
flush_rewrite_rules()
```

### 修复后结果

停用插件：

```text
Source URL → HTTP 200
Spanish WEM URL → 404
Source Data → 不变化
WEM 数据表 → 保留
```

重新启用：

```text
Spanish Route → 自动恢复
Slug → 保留
Translation → 保留
State → 保留
```

结论：

> **Disable Safety 通过。**

## 15. 测试期间发现并修复的重要问题

### 15.1 Canonical Redirect 抢占 Spanish Route

WordPress `redirect_canonical()` 曾把：

```text
/es/about-evodek/
```

拉回：

```text
/about-evodek/
```

修复：

> 仅对 WEM 已识别并允许的目标语言请求抑制 WordPress canonical redirect。

### 15.2 Draft Gate 只有 Header，没有真实 404

早期实现只显示：

```text
X-WEM-ML-Route: gated
```

但页面仍可能正常渲染。

修复：

```text
pre_handle_404
+
WP_Query::set_404()
+
status_header(404)
```

### 15.3 Diagnostics 菜单注册过早导致 Fatal

早期 Diagnostics 直接调用 `add_management_page()`，激活阶段触发：

```text
Call to undefined function wp_get_current_user()
```

修复：

```text
admin_menu
→ 再注册后台页面
```

### 15.4 Diagnostics 回环请求受到缓存干扰

Draft / Published 切换后曾读到旧 HTTP 结果。

修复：

```text
cache-busting query parameter
+
no-cache request headers
```

### 15.5 Disable 时 Rewrite Rule 残留

这是 T09 验收发现的真实架构安全问题。

修复后已通过真实停用 / 启用回归。

## 16. 当前已证明的架构结论

### 结论 1

> **Single Source Page / Post + Runtime Translation Overlay 可行。**

### 结论 2

> **Translation、Publication State、Translated Slug 应保持职责独立。**

### 结论 3

> **Context 定身份，Hash 定版本，State 定发布边界。**

### 结论 4

> **语言 URL 应进入 Core，不应通过 REQUEST_URI Hack 实现。**

### 结论 5

> **完整 Public Path 可以推导，不需要成为不可替代的长期业务真相。**

### 结论 6

> **SEO 必须消费 Route / State 的真实结果，而不是后期补标签。**

### 结论 7

> **Disable Safety 必须真实测试，不能只通过代码阅读判断。**
