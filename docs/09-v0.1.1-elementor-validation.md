## 1. 本轮目标

v0.1.1 不尝试一次支持全部 Elementor Widget。

本轮只验证一条最小但完整的结构化翻译链路：

```text

↓

↓

```

首批字段：

```text

```

## 2. 已验证原则

### 2.1 Elementor Source 必须保持干净

整个实验过程中不把目标语言写回：

```text
_elementor_data
```

Source JSON 通过 SHA-256 辅助确认未被 Translation / Runtime Overlay 污染。

### 2.2 Adapter 决定“哪里可以翻译”

Adapter Registry 当前明确登记：

```text
heading.title
button.text
```

未知 Widget、未知 setting path 不猜、不替换。

### 2.3 Context 定身份，Hash 定版本

当前 locator-backed Context：

```text
elementor:{object_id}:{element_id}:{widget_type}:{setting_path}
```

例如：

```text
elementor:1730:6f3c7fe:heading:title
elementor:1730:fdad941:button:text
```

同一 Context 的 Source 修改后：

```text
Source Unit ID 保持
source_hash 更新
旧 Translation 变 stale
```

### 2.4 element_id 是 Locator，不声明为永久业务身份

当前实现使用 Elementor `element_id` 精确定位 Widget，但架构上仍保留：

> Widget ID 更适合作为当前 Locator，而不是 WEM 永久 Identity。

Widget 删除重建、Page Duplicate、Template Insert 等迁移问题仍属于后续实验。

## 3. Runtime Hook 演进

本轮最重要的实验结论之一，是 Runtime Hook 不能只靠理论判断。

### 尝试 1：before_render

曾通过 Widget 设置修改尝试 Overlay，但 Elementor 的显示设置 / render state / cache 路径使结果不稳定。

结论：

```text
before_render
≠
可靠的唯一 Runtime Overlay 层
```

### 尝试 2：elementor/widget/render_content

Widget-level render hook 在部分请求中可以进入，也保留用于诊断和局部替换。

但实际缓存路径中曾出现 Widget Hook 不进入的情况。

结论：

```text
render_content
可以利用
但不能作为唯一保障
```

### 最终稳定路径：elementor/frontend/the_content

最终在 Elementor 已生成内容后执行结构化 Overlay：

```text
elementor/frontend/the_content
```

这里不是“全文搜索某段 English 再替换”。

流程是：

```text
Adapter-approved field
↓
object_id
↓
element_id
↓
widget_type
↓
setting_path
↓
Source Unit / Translation state
↓
定位 data-id 对应 Widget
↓
只替换该 Widget 内已知 DOM target
```

当前 DOM target：

```text
heading.title
→ .elementor-heading-title

button.text
→ .elementor-button-text
```

因此它属于 **structured locator-scoped overlay**，而不是 global DOM translator。

## 4. Runtime Safety

Runtime Overlay 只有在下列条件同时满足时才应用：

```text
目标语言 = es
Object Language State = published
Source Unit 存在
Source Unit state = active
Live Source Hash = Stored Source Hash
Translation 存在
Translation status = reviewed
translated_from_hash = source_hash
```

任一条件不满足：

```text
fallback source
```

已真实验证：

```text
source-drift
stale
missing translation
published gate
current translation
```

## 7. Cache Invalidation

Runtime 正确不代表访客立即看到最新结果。

实验中真实出现：

```text
Repository = latest
Bypass ES = latest
Normal ES = old
Diagnosis = PAGE CACHE SUSPECTED
```

因此缓存失效被明确拆成独立职责：

```text
WEM_ML_Cache_Invalidator
```

当前策略：

```text
优先 WP Rocket
→ rocket_clean_files()

SiteGround 作为兼容 fallback
→ sg_cachepress_purge_cache()
```

明确不调用：

```text
rocket_clean_domain()
```

WEM v0.1.1 不直接保存或调用 Cloudflare API；当前站点由 WP Rocket 的既有 Cloudflare 集成间接处理。

### 自动触发已验证

```text
Translation change
→ targeted purge PASS

Source Unit change
→ targeted purge PASS

Object Language State change
→ targeted purge PASS

Translated Slug change
→ old ES URL + new ES URL + EN URL targeted purge PASS
```

重复保存相同值：

```text
不重复 purge
```

Manual Purge 按钮继续保留，作为长期诊断 / 回归测试工具。

## 8. Runtime Validation

后台保留：

```text
WEM ML Elementor Runtime Validation
```

当前版本：

```text
Structured Runtime Validation v4
```

它会执行：

```text
EN normal request
ES normal request
ES cache-bypass request
Runtime Trace
Source / Translation Hash comparison
Actual output extraction
Diagnosis
```

当前支持：

```text
heading.title
button.text
```

常见 Diagnosis：

```text
PASS
PAGE CACHE SUSPECTED
ELEMENTOR / RUNTIME CACHE SUSPECTED
ELEMENTOR RUNTIME / ELEMENT CACHE SUSPECTED
LANGUAGE CONTEXT MISMATCH
RUNTIME OUTPUT MISMATCH
```

Validation、Source Sync、Translation Lab、Cache Diagnostics 均作为长期教学、诊断和回归工具保留。

## 11. 当前结论

在当前实验范围内，可以确认：

```text
Single Source
+
Adapter Registry
+
Read-only Elementor Discovery
+
Translation Repository
+
Context / Hash / State
+
Structured Locator-scoped Runtime Overlay
+
Targeted Cache Invalidation
```

这条 Elementor 翻译链路成立。

但当前仍属于：

> **v0.1.1 Experimental / Architecture Validation**

不是 Elementor 全功能生产版。

下一阶段应优先决定：

```text
继续扩展简单 Adapter
or
先研究 Widget Identity Migration
```

而不是直接进入复杂 Widget。
